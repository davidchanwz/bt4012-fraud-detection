# 3.3 Models and justification (draft, R3)

*Draft for the report. About 1 page. No result numbers here; those go in §4.1. Cross-references: §3.1–3.2 (features, R2), §3.4 (evaluation, R4).*

We train three classifiers for the main experiment, each twice: once on the 29 transaction-only features (`txn`) and once on those plus the 23 graph features (`txn+graph`, groups G1, G2, G3 and G5; §3.2). Within each pair the model, the hyperparameter grid, the random seeds and the training rows are identical. The feature set is the only thing that differs, so any difference in performance can be attributed to the graph features.

**Logistic regression (LR)** is the interpretable baseline. It is linear in the features, so its coefficients show which signals matter, and it tells us how much of the graph signal a simple model can use. We use `class_weight="balanced"` so that the 1.3% fraud rows carry as much total weight as the legit rows, and tune the inverse regularisation strength *C* over {10⁻³, …, 10²}. Inputs are standardised on train (count features are log-transformed first), so the coefficients are comparable in size.

**Feedforward neural network (MLP)** is the non-linear model from our proposal. We keep it small (one layer of 32 or two layers of 64 and 32 units, L2 penalty α ∈ {10⁻⁴, 10⁻²}) and use early stopping on a 10% hold-out of the training data. Imbalance is handled by undersampling: each fit uses all train fraud and 10 randomly drawn legit rows per fraud. The sample depends only on the seed, so the `txn` and `txn+graph` networks see exactly the same rows. Neural networks are sensitive to initialisation, so every configuration is trained with 5 seeds. The configuration is chosen by mean validation PR-AUC, its score is the average of the 5 networks' probabilities, and we report the standard deviation across seeds.

**LightGBM** (gradient-boosted trees) is the standard strong baseline for tabular fraud data. Trees capture interactions (for example, a small amount at a merchant with high past fraud) without feature engineering, and training is fast enough on a CPU to make the ablation in §4.2 cheap. Imbalance is handled with `scale_pos_weight` (legit-to-fraud ratio in train). We tune the number of leaves {15, 31, 63}, learning rate {0.05, 0.1} and minimum leaf size {20, 100}, with up to 1,000 trees and early stopping on validation PR-AUC. Graph features are fed unscaled, since trees don't need it.

**Random forest (robustness check).** After proposal feedback we added a random forest, to check that the graph features help across model families and not only for the three above. It is a bagged-tree model, unlike LightGBM's boosted trees. We use 300 trees with `max_features="sqrt"` and `class_weight="balanced_subsample"`, and tune the maximum depth {20, unlimited} and minimum leaf size {1, 5, 20} on validation PR-AUC. Leaf size matters here: validation PR-AUC was clearly lower at 20 than at 1 or 5, so the grid includes small leaves. Graph features are fed unscaled. It is reported in the appendix, not the main table, so the headline comparison stays three models. We did not add XGBoost: it is a boosted-tree library close to LightGBM and would add little evidence beyond it. We did not try a graph neural network, which is left as future work (§5).

**Tuning protocol.** All models are fitted on the training split (days 0–119) and tuned by PR-AUC on the validation split (days 120–149), the primary metric (§3.4). We don't refit on train plus validation: the validation split also sets the decision threshold used on test, and refitting would change the score distribution that threshold was chosen for. The test split (days 150–179) is scored once, after results were frozen, and no choice was made with it.

**Why the imbalance handling is acceptable.** Class weights, `scale_pos_weight` and undersampling all distort predicted probabilities, so scores are not calibrated fraud probabilities. They do preserve the ranking of transactions, which is what PR-AUC and the review-budget metrics measure. The F1 threshold is chosen on validation scores from the same model, so it is consistent with the distorted scale.

**Limitations.** The grids are small, chosen to keep the comparison fair and cheap rather than to squeeze out the last point of accuracy. We use one chronological split, so results reflect one month of test data. BankSim is simulated, so feature effects (§4.4) may reflect how the simulator generates fraud rather than real fraud behaviour.
